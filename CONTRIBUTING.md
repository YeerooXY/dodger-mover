# Contributing

Development is organized around bounded vertical slices rather than an unrestricted backlog.

Before opening a pull request:

1. Link the active slice document.
2. State the player-facing behavior changed.
3. List what is deliberately out of scope.
4. Run the repository guard and relevant Unity tests.
5. Add provenance for every new asset.

Pull requests should remain small enough to review as one coherent outcome. Mechanical refactors and gameplay changes should be separate unless the refactor is strictly required by the slice.
